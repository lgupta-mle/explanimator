## Codebase Patterns
- Config lives in `src/research_viz/config/pipeline_config.py`; use `get_config()` singleton accessor
- YAML config at project root `config.yaml`; env overrides via `ANVAYA_*` prefix with `__` nesting (e.g. `ANVAYA_LLM__EXPLANATION_MODEL`)
- Use `reset_config()` in tests to clear singleton state
- Tests go in `tests/` directory; run with `python3 -m pytest tests/ -v`
- Project uses pydantic for schemas, pydantic-settings for config
- LLM calls go through OpenRouter (prefix models with provider e.g. `openai/gpt-5`)
- All modules read model names, timeouts, and worker counts from `get_config()` — no hardcoded values in business logic
- Pattern for config migration: change default to `Optional[str] = None`, resolve via `get_config()` at top of function body
- Profile YAMLs live in `config/` dir (sibling to `config.yaml`); selected via `ANVAYA_PROFILE` env var (default: `dev`)
- Resolution order: env vars > profile YAML > base config.yaml > field defaults
- Tests that construct `PipelineConfig()` directly must set `ANVAYA_CONFIG_PATH` to an isolated tmp path to avoid picking up real project config + dev profile
- Files that don't exist per PRD (translator.py, video_renderer.py, constants.py, code_generator.py) — code_gen is in `pdf_to_manim_pipeline.py`, others were removed in prior refactors
- LLM provider abstraction lives in `src/research_viz/providers/`; use `get_provider()` singleton from `pipeline_config.py`
- `reset_config()` also resets the provider singleton; use `reset_provider()` to reset only the provider
- All LLM calls now go through `get_provider().generate()` — never call OpenRouter/OpenAI directly
- Use `call_llm_provider()` from `pdf_explanation_generator.py` as convenience wrapper (handles schema→response_format, plugins)
- Provider tracks per-call stats via `provider.call_stats`, `provider.total_tokens`, `provider.total_calls`
- When updating tests that mock LLM calls, mock `get_provider` to return a MagicMock with `.generate()` returning `LLMResponse`
- `CallStat` has `tokens_in`, `tokens_out`, and `stage` fields; use `provider.set_stage("name")` before calls to attribute them
- Run metrics module at `src/research_viz/pipeline/run_metrics.py`; `RunMetricsCollector` wraps start/stop timing + `collect(provider)` → dict + `write(provider, dir)` → JSON
- Model pricing lives in `llm.model_pricing` config as dict of `ModelPricing(input, output)` per-token USD rates
- `run_pipeline()` runs TTS and code gen in parallel via `ThreadPoolExecutor(max_workers=2)` after explanation generation; fail-fast on either failure
- `sync_video_audio_single_pass()` combines speed adjust (setpts) + pad (tpad) + audio merge in one ffmpeg call — always prefer this over the two-step chain
- Legacy `adjust_video_to_audio_duration()` and `sync_audio_with_video()` are kept as thin wrappers for backward compat
- `render_and_sync_all_scenes` uses producer-consumer pattern: render pool feeds sync pool via `ThreadPoolExecutor`; configure via `video.render_workers` and `video.sync_workers`
- `_render_scene()` and `_sync_scene()` are extracted helpers for single-scene render and sync; test them individually
- Model tiering: use `get_config().llm.get_model("explanation_model", difficulty)` to resolve per-difficulty model; falls back to base if tier not set
- `TierConfig` has `skip_judge: bool` for per-difficulty behavior toggles; access via `get_config().llm.get_tier(difficulty)`
- `generate_with_feedback_loop` and `generate_explanation_from_pdf` accept `difficulty` param; pass it to use tier-specific models and skip_judge
- `_validate_segment_count(content)` checks 2-3 segment range — always runs even when judge is skipped
- Checkpoint module at `src/research_viz/pipeline/checkpoint.py`; use `write_checkpoint(run_dir, stage, paths)` after each stage, `read_checkpoints(run_dir)` to load, `validate_checkpoint(cp)` to verify hashes
- `run_pipeline` has `force_restart` param; `main()` exposes it as `--force-restart` CLI flag
- Partial audio resume: `generate_segment_beats` skips beats with existing valid WAV files; corrupted files trigger regeneration
- All modules use `logging.getLogger(__name__)` — no print() in src/research_viz/ (except README examples)
- Log config in `src/research_viz/__init__.py`: format `%(asctime)s %(levelname)s %(name)s: %(message)s`
- `RunMetricsCollector.time_stage(name, provider)` context manager for per-stage wall-clock timing with token/call delta tracking
- `RunMetricsCollector.record_error(stage, exc, artifact_id, recoverable)` for structured error logging in metrics

## 2026-03-21 - US-008
