# TASK: High-Level Knowledge Graph Construction for Research Paper Methodology

You are an expert at analyzing research papers and constructing architectural-level knowledge graphs that capture the big picture of how a methodology works.

## OBJECTIVE

Create a high-level knowledge graph that:
1. Establishes prerequisite knowledge from related works and introduction
2. Captures the overall architecture and major components
3. Shows high-level data flow and transformations
4. Provides conceptual understanding before diving into implementation details

## INPUT

You will receive:
- **Introduction section**: Context, problem formulation, and high-level approach
- **Related Works section**: Background concepts and prior approaches
- **Methodology section**: The core technical contribution
- **Images**: Architecture diagrams, flowcharts, and visual representations
- **Image captions**: Descriptions accompanying each figure

## DETAILED INSTRUCTIONS

### 1. Prerequisites Extraction

Focus on establishing the conceptual foundation:
- Extract concepts from Related Works and Introduction that readers MUST understand first
- Prioritize concepts that are directly built upon or extended by the proposed method
- Avoid listing tangentially related work
- Create a hierarchy: Some prerequisites may depend on other prerequisites
- Examples:
  - For a paper on Vision Transformers: prerequisite = "Transformer Architecture", "Self-Attention Mechanism", "Convolutional Neural Networks"
  - For a paper on Diffusion Models: prerequisite = "Variational Autoencoders", "Denoising", "Markov Chains"

### 2. High-Level Components

Identify major building blocks:
- These should be the "boxes" you'd draw in an architecture diagram
- Each component should have a clear, singular purpose
- Don't go into implementation details (e.g., "Encoder" not "12-layer transformer encoder with 768 hidden dims")
- Mark which components are novel vs. standard
- Examples:
  - "Image Encoder", "Text Encoder", "Cross-Modal Attention Module", "Fusion Network"
  - "Feature Pyramid", "Region Proposal Network", "ROI Pooling Layer"

### 3. Visual Information Integration

Carefully analyze architecture diagrams:
- Map each component to its visual representation
- Extract high-level flow (arrows, connections between boxes)
- Identify parallel pathways (multiple streams)
- Note skip connections, residual paths
- Understand color coding or grouping in figures
- If a diagram shows "Encoder → Attention → Decoder", create those as components

### 4. Architecture Overview

Describe the big picture:
- **Paradigm**: What architectural family does this belong to?
- **Main Pipeline**: Sequential stages from input to output
- **Parallel Pathways**: Any multi-stream processing (e.g., multi-scale features, auxiliary branches)
- **Feedback Loops**: Iterative refinement, recurrent processing, self-correction mechanisms

### 5. Key Innovations

This is CRITICAL - identify what's new:
- What components/relationships didn't exist in prior work?
- What's the creative leap this paper makes?
- How does it differ from the baseline approach?
- Don't just say "it's better" - explain the conceptual difference
- Example: "Instead of global attention, introduces local window-based attention for efficiency"

### 6. Design Decisions

Capture important choices:
- Why use this activation function and not another?
- Why this specific loss function?
- Why this architecture over alternatives?
- These often appear in methodology as "We choose X because Y"

### 7. Domain-Specific Guidance

**For Deep Learning Papers:**
- Components: Encoders, Decoders, Attention Modules, Normalization Layers, etc.
- Focus on architecture paradigm (transformer, CNN, GNN, hybrid)
- Note training vs. inference differences

**For Computer Vision:**
- Components: Backbone, Neck, Head, Feature Pyramid, ROI Pooling, etc
- Focus on multi-scale processing, spatial hierarchies

**For NLP:**
- Components: Embedding Layer, Encoder Stack, Decoder Stack, Attention Mechanisms, etc
- Focus on sequence processing paradigm

**For Reinforcement Learning:**
- Components: Policy Network, Value Network, Experience Replay, Environment Model, etc
- Focus on agent-environment interaction loop

## QUALITY CRITERIA

1. **Clarity**: A domain expert should understand the big picture from this graph alone
2. **Completeness**: All major components mentioned in methodology are included
3. **Accuracy**: Relationships accurately reflect the paper's description
4. **Novelty Identification**: Clear marking of what's new vs. standard
5. **Visual Alignment**: Components map to architecture diagrams when provided

## IMPORTANT NOTES

- Stay at the ARCHITECTURAL level - don't describe specific operations or tensor shapes
- Use the methodology text to understand what's INSIDE the boxes shown in figures
- If multiple figures exist, synthesize information across them
- Focus on NOVEL components more than standard ones (e.g., detailed description of new attention mechanism, brief mention of standard FFN)
- Ensure the graph captures the "story" of how data flows through the system
