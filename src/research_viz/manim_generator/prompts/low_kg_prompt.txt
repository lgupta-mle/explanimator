## DETAILED INSTRUCTIONS

### 1. Atomic Operation Extraction

For each high-level component, decompose into atomic operations:
- **Linear/Dense layers**: Separate into matrix multiplication + bias addition
- **Attention mechanisms**: Break into Q/K/V projections → dot product → scaling → softmax → weighted sum
- **Normalization layers**: Separate into mean/variance computation → normalization → scale/shift
- **Activation functions**: Each activation (ReLU, GELU, Sigmoid, etc.) is an atomic operation
- **Reshape/Transpose operations**: Often implicit but critical for tensor flow

Examples of atomic operations:
```
- "linear_projection": W @ X + b
- "matrix_multiply": A @ B
- "scaled_dot_product": (Q @ K^T) / sqrt(d_k)
- "softmax": exp(x) / sum(exp(x))
- "layer_norm": (x - mean) / sqrt(var + eps) * gamma + beta
- "gelu_activation": x * Phi(x) where Phi is Gaussian CDF
- "dropout": x * bernoulli(p) / p (training), x (inference)
- "concatenate": torch.cat([x1, x2], dim=-1)
- "split_heads": x.view(batch, seq, num_heads, d_k).transpose(1, 2)
```

### 2. Tensor Shape Tracking

This is CRITICAL for code generation:
- Track shape at every step in the data flow
- Be explicit about dimension meanings: `[batch, seq_len, hidden_dim]` not just `[B, S, H]`
- Show how shapes change through operations:
  - Matrix multiply: `[B, M, K] @ [K, N] → [B, M, N]`
  - Reshape for multi-head: `[B, S, D] → [B, S, H, D/H] → [B, H, S, D/H]`
  - Concatenation: `[B, S, D1]` + `[B, S, D2] → [B, S, D1+D2]`
- Note broadcasting behavior where applicable

### 3. Mathematical Formulas

Provide precise LaTeX formulas:
- Use standard notation (capital letters for matrices, lowercase for vectors)
- Show element-wise vs. matrix operations clearly
  - Element-wise: `x ⊙ y` or `x * y`
  - Matrix multiply: `X @ Y` or `XY`
- Include all terms (don't omit bias terms or normalization constants)
- Match the notation used in the paper when possible

Examples:
```latex
Q = XW_Q + b_Q
\text{Attention}(Q,K,V) = \text{softmax}(\frac{QK^T}{\sqrt{d_k}})V
\text{LayerNorm}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta
```

### 4. Parameters vs. Hyperparameters

Distinguish clearly:
- **Parameters**: Learned weights (W, b, gamma, beta)
  - Include shape, initialization strategy, whether trainable
- **Hyperparameters**: Fixed configuration values (num_heads=8, d_k=64, dropout=0.1)
  - Include in hyperparameters dict

### 5. Data Flow Construction

Create a step-by-step trace:
```json
{
  "step": 1,
  "operation_id": "project_to_query",
  "input_from": ["component_input"],
  "output_to": ["reshape_query"],

  "tensor_shape_at_step": "[batch, seq_len, d_model]",
  "notes": "Uses weight matrix W_Q with Xavier initialization"
}
```

Order matters! Number steps sequentially as they execute.

### 6. Composite Operations

Some operations are commonly grouped:
- **Scaled Dot-Product Attention**: QK^T → scale → mask (optional) → softmax → @V
- **Multi-Head Attention**: Project to Q/K/V → split heads → scaled dot-product → concat → project
- **Feed-Forward Network**: Linear → activation → dropout → Linear
- **Residual Connection + LayerNorm**: residual = x, x = operation(x), x = LayerNorm(x + residual)

Group these to show higher-level patterns while maintaining atomic details.

### 7. Tensor Transformations

Reshape/transpose operations are often the trickiest part:
```json
{
  "from_shape": "[batch, seq_len, d_model]",
  "to_shape": "[batch, num_heads, seq_len, d_k]",
  "transformation_type": "reshape_transpose",
  "purpose": "Split embedding dimension into num_heads for parallel attention",
  "formula_or_code": "x.view(batch, seq_len, num_heads, d_k).transpose(1, 2)"
}
```

Be explicit about which dimensions are moved/combined.

### 8. Special Cases

Capture conditional behavior:
- **Training vs. Inference**: Dropout, batch norm behavior
- **Masking**: Causal masks for autoregressive models, padding masks
- **Sequence length variations**: Dynamic shapes, padding handling
- **Edge cases**: Empty sequences, single-token inputs

### 9. Implementation Hints

Provide practical guidance:
- **Memory efficiency**: Gradient checkpointing, in-place operations
- **Numerical stability**: LogSumExp trick for softmax, epsilon in normalization
- **Gradient flow**: Residual connections, gradient clipping points
- **Performance**: Batching strategies, kernel fusion opportunities

### 10. Visualization Suggestions

For each operation, suggest how to animate:
- **High priority**: Novel operations, complex transformations, attention patterns
- **Medium priority**: Standard operations in novel configurations
- **Low priority**: Completely standard operations (basic ReLU, etc.)

Visualization types:
- `tensor_flow`: Show tensor moving through operations with shape changes
- `matrix_animation`: Animate matrix multiplication, attention computation
- `attention_heatmap`: Visualize attention weights
- `dimension_transformation`: Show reshape/transpose visually

## DOMAIN-SPECIFIC GUIDANCE

### Deep Learning - Attention Mechanisms

Decompose attention into:
1. Linear projections: X → Q, K, V
2. Reshape for multi-head: `[B,S,D] → [B,H,S,D/H]`
3. Scaled dot-product: `QK^T / sqrt(d_k)`
4. Optional masking: Add `-inf` to masked positions
5. Softmax: Row-wise normalization
6. Weighted sum: Attention @ V
7. Reshape back: `[B,H,S,D/H] → [B,S,D]`
8. Output projection: Linear layer

### Deep Learning - Convolutions

Decompose convolution into:
1. Input padding (if needed)
2. Im2col transformation (unfold)
3. Matrix multiplication with kernel
4. Reshape to output spatial dimensions
5. Bias addition
6. Activation function

Track: kernel size, stride, padding, dilation, groups

### Deep Learning - Normalization

**Layer Normalization**:
1. Compute mean: `μ = mean(x, dim=-1)`
2. Compute variance: `σ² = var(x, dim=-1)`
3. Normalize: `x_norm = (x - μ) / sqrt(σ² + ε)`
4. Scale and shift: `y = γ * x_norm + β`

**Batch Normalization**:
1. Compute batch statistics (training) or use running stats (inference)
2. Normalize
3. Scale and shift

### Computer Vision - Feature Pyramids

Track:
- Spatial dimensions at each level
- Upsampling/downsampling operations (stride-2 conv, max pool, interpolation)
- Feature concatenation or addition across levels
- Channel dimension changes

### NLP - Positional Encoding

Decompose:
1. Generate position indices: `[0, 1, 2, ..., seq_len-1]`
2. Generate dimension indices: `[0, 1, 2, ..., d_model-1]`
3. Compute sinusoidal encoding: `PE(pos, 2i) = sin(pos / 10000^(2i/d_model))`
4. Element-wise addition: `x = x + PE`

## QUALITY CRITERIA

1. **Completeness**: Every operation in the component is captured
2. **Precision**: Tensor shapes and formulas are exactly correct
3. **Executability**: Enough detail to implement in code
4. **Clarity**: Operations are well-organized and documented
5. **Correctness**: Mathematical formulas match the paper

## IMPORTANT NOTES

- Go BEYOND what's shown in figures - read methodology text carefully
- If a detail is not specified (e.g., initialization), use standard practices and note it
- Don't skip "obvious" operations like activation functions or bias terms
- For complex components, create 20-50 atomic operations
- Ensure data_flow creates a complete directed acyclic graph
