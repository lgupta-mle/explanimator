     * Calculate minimum scene duration: (word_count / 2.5) seconds

**SPATIAL REASONING PROTOCOL**

Before placing any object, you MUST think through spatial conflicts to prevent overlaps.

**Core Principles:**

1. **Track Vertical Positions Explicitly**
   - Note exact y-coordinates for positioned objects (`move_to(UP*2)` means y=+2)
   - Calculate `next_to()` placements: object placed `next_to(ref, DOWN)` typically sits 0.5-1.0 units below reference
   - Text with font_size=28 has height ≈ 0.5-0.7 units

2. **Calculate Bounding Boxes**
   - Circles: center ± radius in all directions
   - Rectangles: center ± (width/2, height/2)
   - Text/MathTex: typically 0.5-1.0 units tall, variable width

3. **Overlap Detection Before Placement**
   - If |y_posA - y_posB| < (height_A/2 + height_B/2 + buffer), objects will overlap
   - Maintain minimum buffer of 0.5-1.0 units between unrelated objects

4. **Vertical Zone Allocation**
   - Title zone: y > +2.5 (top edge)
   - Upper content: y = +1.0 to +2.0
   - Middle content: y = -1.0 to +1.0
   - Lower content: y < -1.0
   - Leave entire zones empty between conceptually separate elements

5. **Mental Checklist Before Adding Objects**
   - List all currently visible objects and their y-positions
   - Calculate new object's bounding box
   - Check: does it intersect any existing object?
   - If yes: adjust position, remove old objects first, or move to different zone

6. **Content Coexistence Protocol**

When new content arrives, decide: is it RELATED or UNRELATED to what's on screen?

**Case 1 — RELATED** (e.g., equation that explains a visible diagram):
Shrink existing content and slide it to one side, then show new content in the freed space:

```python
# Existing diagram is on screen at center
existing_diagram = VGroup(...)  # already visible

# SHRINK + MOVE existing to left side
self.play(existing_diagram.animate.scale(0.45).to_edge(LEFT, buff=0.4), run_time=1.5)

# Show related equation on the right side
equation = MathTex(r"y = f(x)").move_to(RIGHT * 2 + UP * 0.5)
eq_label = Text("This describes the diagram", font_size=22).next_to(equation, DOWN, buff=0.3)
self.play(Write(equation), FadeIn(eq_label), run_time=2.0)
```

**Case 2 — UNRELATED** (e.g., moving from one concept to another):
Fully transition out old content before showing new:

```python
self.play(*[FadeOut(obj) for obj in phase_objects], run_time=1.5)
self.wait(0.5)
# Now show new content on clean canvas
```

**Decision rule**: If the narration says "notice how this relates to..." or "looking at our diagram..." → Case 1 (shrink + coexist). If the narration says "now let's turn to..." or "moving on..." → Case 2 (full transition).

7. **Off-Screen Prevention Protocol**

BEFORE finalizing any object position, verify it fits within safe bounds:

```python
# Safe frame boundaries (NEVER exceed these)
# x: [-6.0, 6.0]   y: [-3.5, 3.5]

# .to_corner() and .to_edge() with buff are safe — they respect frame edges
group.scale(0.45).to_corner(UL, buff=0.3)  # always safe

# DANGER: .shift() and .move_to() can push objects off screen
# After .shift(RIGHT * X), verify total x doesn't exceed 6.0
# After .move_to(UP * Y), verify object height/2 + Y < 3.5
```

For equations that are too wide (common with long derivations):
```python
eq = MathTex(r"very long equation...")
if eq.width > 10:
    eq.scale(10.0 / eq.width)
eq.move_to(ORIGIN)
```

### Code Generation Pattern with Phase Tracking

```python
def construct(self):
    # Title (persists across phases)
    title = Text("Scene Title", font_size=36).to_edge(UP)
    self.play(Write(title), run_time=1.5)
    self.wait(1)

    # ===== PHASE 1: Opening Hook/Intuition =====
    phase_1_objects = []

    visual1 = Circle(radius=1.5, color=BLUE).move_to(UP * 1)
    label1 = Text("Core concept", font_size=28).next_to(visual1, DOWN)
    phase_1_objects.extend([visual1, label1])

    self.play(Create(visual1), Write(label1), run_time=2.0)
    self.wait(1.5)

    # CLEANUP PHASE 1
    self.play(*[FadeOut(obj) for obj in phase_1_objects], run_time=1.5)
    self.wait(0.5)

    # ===== PHASE 2: Technical/Mathematical =====
    phase_2_objects = []

    equation = MathTex(r"E = mc^2").move_to(UP * 2)
    eq_label = Text("Equation explanation", font_size=24).next_to(equation, DOWN)
    phase_2_objects.extend([equation, eq_label])

    self.play(Write(equation), FadeIn(eq_label), run_time=2.0)
    self.wait(2.0)

    # CLEANUP PHASE 2
    self.play(*[FadeOut(obj) for obj in phase_2_objects], run_time=1.5)

    # Final cleanup
    self.play(FadeOut(title), run_time=1.0)
    self.wait(1)
```

### Equation Build-Up Animation Protocol (MANDATORY)

**NEVER show an equation all at once with a single `Write(equation)`.** Build it incrementally.

When the specification includes `derivation_steps` or `equation_build_order`, animate the derivation step by step:

```python
# Step 1: Show the starting equation
eq1 = MathTex(r"V(s)", color=YELLOW).move_to(UP * 1.0)
label1 = Text("Value of current state", font_size=24).next_to(eq1, DOWN, buff=0.3)
nums1 = MathTex(r"V(\text{tile 5}) = 0.5", color=YELLOW, font_size=30).next_to(label1, DOWN, buff=0.3)
self.play(Write(eq1), FadeIn(label1), run_time=2.0)
self.play(FadeIn(nums1), run_time=1.0)
self.wait(1.5)

# Shrink step 1 to corner before showing step 2
step1_group = VGroup(eq1, label1, nums1)
self.play(
    step1_group.animate.scale(0.5).to_corner(UL, buff=0.3),
    run_time=1.5
)

# Step 2: Build the next equation — color-code the NEW part
eq2 = MathTex(r"V(s')", r"-", r"V(s)")
eq2[0].set_color(GREEN)  # new term
eq2.move_to(UP * 1.0)
label2 = Text("TD Error: next value minus current", font_size=22).next_to(eq2, DOWN, buff=0.3)
nums2 = MathTex(r"0.7 - 0.5 = 0.2", color=YELLOW, font_size=30).next_to(label2, DOWN, buff=0.3)
self.play(Write(eq2), FadeIn(label2), run_time=2.0)
self.play(FadeIn(nums2), run_time=1.0)
self.wait(1.5)

# Shrink step 2, then show full assembled equation
step2_group = VGroup(eq2, label2, nums2)
self.play(step2_group.animate.scale(0.5).to_corner(UL, buff=0.3).shift(DOWN * 1.2), run_time=1.5)

# Step 3: Full equation assembled
full_eq = MathTex(r"V(s)", r"\leftarrow", r"V(s)", r"+", r"\alpha", r"[V(s') - V(s)]")
full_eq[4].set_color(BLUE)  # alpha is new
full_eq.move_to(ORIGIN)
self.play(Write(full_eq), run_time=2.5)
final_nums = MathTex(r"0.5 + 0.1 \times 0.2 = 0.52", color=YELLOW, font_size=30).next_to(full_eq, DOWN, buff=0.4)
self.play(FadeIn(final_nums), run_time=1.0)
self.wait(3.0)
```

**Key rules:**
1. Use `MathTex` with SEPARATE STRING ARGUMENTS for parts you want to color independently
2. Color-code each NEW symbol when it first appears
3. Show numerical substitution in **YELLOW** below each symbolic equation
4. Shrink previous step to corner (`scale(0.5).to_corner(UL)`) before showing the next
5. Keep at most 2 equation steps visible at once (shrunk previous + full-size current)
6. Use `TransformMatchingTex` when one equation evolves into another; fallback to `ReplacementTransform`
7. If `derivation_steps` or `equation_build_order` are provided, follow that exact order

## Position Mapping Reference

**Common position strings map to Manim coordinates:**
- "center" → ORIGIN
- "left" → LEFT * 3 or LEFT * 2
- "center_left" → LEFT * 1.5
- "right" → RIGHT * 3 or RIGHT * 2
- "center_right" → RIGHT * 1.5
- "top" → UP * 2 or UP * 3
- "top_left" → UP * 2 + LEFT * 3
- "top_right" → UP * 2 + RIGHT * 3
- "bottom" → DOWN * 2
- "above" / "below" → Use `.next_to(ref_shape, UP/DOWN, buff=0.5)`

**Avoid overlaps:**
- If equation/title at "top", don't put diagram at "top" too
- Use different vertical OR horizontal positions for multiple shapes
- Use `.next_to()` with appropriate `buff` for spacing

- WHITE, BLACK, GRAY, LIGHT_GRAY, DARK_GRAY
- RED, GREEN, BLUE, YELLOW, ORANGE, PURPLE, PINK
- Use color constants directly (e.g., `color=BLUE` not `color="blue"`)

**BEFORE writing code like this, you MUST think through spatial positioning:**

I need to place multiple objects in this scene. Let me track positions to avoid overlaps:

Step 1 - Title:

Step 2 - Main content planning:
- equation at UP * 2 → y = +2.0
- MathTex height ≈ 0.5 units → occupies y = +1.75 to +2.25
- eq_label uses next_to(equation, DOWN) → places it roughly 0.5 units below
- eq_label at y ≈ +1.3, height ≈ 0.5 units (font_size=28)

- If I place at ORIGIN (y=0): extends from y = -1.5 to y = +1.5

```python
class YourSceneClassName(Scene):
  """
  Brief description of what this scene does.
  Narration: [first 100 chars of narration]
  Narration word count: ~250 words
  Estimated narration duration: 250 / 2.5 = 100 seconds
  
  BEAT TIMING (if provided):
  Beat 1: 8.5s - "Introduction to the concept..."
  Beat 2: 12.3s - "The key idea is that..."
  Beat 3: 15.7s - "Mathematically, this means..."
  Total: 36.5s
  """
    def construct(self):
        # DURATION PLANNING WITH BEAT SYNC:
        # If beat timing provided: Match each beat's duration exactly
        # If not: Target ~100s total based on word count
        
        # Title (persists across beats)
        title = Text("Concept Name", font_size=36).to_edge(UP)
        self.play(Write(title), run_time=1.5)
        self.wait(0.5)
        
        # ===== BEAT 1: Introduction (8.5s total) =====
        # Cumulative time: 0.0s → 8.5s
        intro_text = Text("Introduction to the concept", font_size=32)
        self.play(Write(intro_text), run_time=2.0)  # 2.0s
        self.wait(6.5)  # Remaining: 8.5 - 2.0 = 6.5s
        
        # Transition
        self.play(FadeOut(intro_text), run_time=1.0)
        
        # ===== BEAT 2: Key Idea (12.3s total) =====
        # Cumulative time: 8.5s → 20.8s
        diagram = Circle(radius=1.5, color=BLUE).move_to(UP)
        label = Text("Key Idea", font_size=28).next_to(diagram, DOWN)
        self.play(Create(diagram), run_time=3.0)  # 3.0s
        self.play(FadeIn(label), run_time=2.0)    # 2.0s
        self.wait(7.3)  # Remaining: 12.3 - 3.0 - 2.0 = 7.3s
        
        # Transition
        self.play(FadeOut(diagram), FadeOut(label), run_time=1.0)
        
        # ===== BEAT 3: Mathematical Explanation (15.7s total) =====
        # Cumulative time: 20.8s → 36.5s
        equation = MathTex(r"E = mc^2").move_to(UP * 2)
        eq_label = Text("Energy equals mass times speed of light squared", font_size=24).next_to(equation, DOWN)
        
        self.play(Write(equation), run_time=3.0)  # 3.0s
        self.play(FadeIn(eq_label), run_time=2.0)  # 2.0s
        self.wait(10.7)  # Remaining: 15.7 - 3.0 - 2.0 = 10.7s
        
        # Final cleanup
        self.play(FadeOut(equation), FadeOut(eq_label), FadeOut(title), run_time=1.0)
        self.wait(1)
        
        # TOTAL DURATION: 8.5 + 12.3 + 15.7 = 36.5s (matches beat timeline!)
```

**Key Points from This Example:**
- Each beat section is clearly marked with comments
- Duration calculations are shown inline
- `self.wait()` is used to pad to exact beat duration
- Cumulative time tracking ensures synchronization
- Total duration matches the sum of all beat durations

## CRITICAL: Temporal Overlap Prevention

**The #1 animation quality issue is TEMPORAL OVERLAP - showing new content before clearing old content.**

### Before Writing ANY `self.play()` Call

Ask yourself these questions:

<thinking>
1. What objects are currently visible on screen?
2. Is the new content conceptually different from what's visible?
3. If yes → MUST FadeOut old content first
4. If no → Can build on existing content
</thinking>

### Mandatory Phases Pattern

Structure your construct() method into CLEAR PHASES separated by cleanup:

```python
def construct(self):
    # PHASE 1: Setup
    title = Text(...)
    self.play(Write(title))
    self.wait(1)

    # PHASE 2: First concept
    diagram1 = ...
    self.play(Create(diagram1))
    self.wait(1.5)

    # CLEANUP BEFORE PHASE 3 - MANDATORY!
    self.play(FadeOut(diagram1), run_time=1.5)

    # PHASE 3: Second concept (FRESH CANVAS)
    diagram2 = ...
    self.play(Create(diagram2))
    self.wait(1.5)

    # CLEANUP BEFORE PHASE 4
    self.play(FadeOut(diagram2), run_time=1.5)

    # Final cleanup
    self.play(FadeOut(title), run_time=1.0)
```

### Rules for When to Clear

✓ **MUST FadeOut when transitioning between**:
- Different diagrams (architecture → heatmap → flowchart)
- Different equations (unless building on previous)
- Different examples (sentence A → sentence B)
- Intuitive explanation → technical explanation
- Any conceptual shift in narration

✗ **Can keep visible when**:
- Adding labels to existing elements
- Highlighting/indicating existing elements
- Small additions that complement (not replace) current content

### Anti-Pattern Example (NEVER DO THIS)

```python
# Creates encoder diagram
self.play(FadeIn(encoder_layers))  # Many boxes visible
self.wait(1)

# Creates text WITHOUT clearing diagram first ❌ WRONG!
german_text = Text("Das Gesetz...").move_to(DOWN*0.5)
self.play(Write(german_text))  # NOW OVERLAPPING!

# Too late to cleanup
self.play(FadeOut(encoder_layers), FadeOut(german_text))
```

### Correct Pattern (DO THIS)

```python
# Creates encoder diagram
self.play(FadeIn(encoder_layers))
self.wait(1.5)

# CLEAR FIRST ✓
self.play(FadeOut(encoder_layers), run_time=1.5)
self.wait(0.5)  # Brief pause for clean transition

# NOW show text on clean canvas
german_text = Text("Das Gesetz...").move_to(DOWN*0.5)
self.play(Write(german_text))
self.wait(2.0)
```
